# Configuration reference

Generated from `internal/config`'s structs (`go run ./tools/gendocs`) — key names, env var names, types, and defaults come directly from the code that parses them; only the descriptions are hand-authored. Regenerate after changing any config struct.

Layering: **defaults → YAML config file(s) → environment variable overrides** (highest precedence wins). One config document covers every subcommand (`public`, `metrics`, and `storage` sections together) — pass it with `argvio --config path/to/argvio.yaml <command>` (`-c` repeatable: later files override earlier ones), mirroring ory/hydra's single `hydra.yml`. See [`argvio.example.yaml`](../argvio.example.yaml) for a full example. Env vars use prefix `ARGVIO_` and `__` as the nesting delimiter (plain `_` is legal inside a key name), e.g. `ARGVIO_STORAGE__PUBLIC_POOL__MAX_CONNS`. List-valued keys take a comma-separated value in an env var, e.g. `ARGVIO_METRICS__CORS__ALLOWED_ORIGINS=https://a.example.com,https://b.example.com`.

## `public` server (`argvio serve public`)

| `log_level` | `ARGVIO_LOG_LEVEL` | string | `info` | Log level: debug, info, warn, error. |
| `auth.methods` | `ARGVIO_AUTH__METHODS` | []string | `[api_key jwt]` | Which auth methods this deployment accepts, in any combination: api_key (scoped tenant API key), jwt (dashboard-user session, HS256, requires jwt_signing_key), oidc (OAuth2 access tokens from a third-party OIDC provider, as JWTs or, with oidc.introspection, opaque tokens; requires oidc.issuer_url and oidc.audience). Global — shared by both the public and metrics servers; each still only accepts its own tenant API-key scope (public_ingest vs metrics_query). A token is routed by shape, not tried against each method: an `argv_` prefix is an API key, a three-part JWS is jwt (HS256) or oidc (asymmetric alg), and any other token is introspected if oidc.introspection.enabled, else treated as an API key. |
| `auth.jwt_signing_key` | `ARGVIO_AUTH__JWT_SIGNING_KEY` | string | `` | HMAC secret for verifying jwt-method tokens. Required when auth.methods includes jwt. |
| `auth.oidc.issuer_url` | `ARGVIO_AUTH__OIDC__ISSUER_URL` | string | `` | OIDC issuer, exactly as the provider's discovery document states it. A trailing slash is significant (`https://idp.example.com/` and `https://idp.example.com` are different issuers): the value is compared byte for byte with the discovery `issuer`, each token's `iss`, and `tenant_members.issuer`. Discovery and the JWKS are fetched (and cached) at request time. Required when auth.methods includes oidc. |
| `auth.oidc.audience` | `ARGVIO_AUTH__OIDC__AUDIENCE` | string | `` | Resource identifier of the metrics API (e.g. `https://api.example.com`), which every token's `aud` must contain. It must NOT equal any SPA's `client_id`: an ID token's `aud` is the client_id, so keeping the two different is what stops an ID token being accepted as an access token. Required when auth.methods includes oidc. |
| `auth.oidc.required_scopes` | `ARGVIO_AUTH__OIDC__REQUIRED_SCOPES` | []string | `[]` | OAuth2 scopes that must all be present (via the `scope` or `scp` claim, or the introspection response) for a token to be accepted; a token that lacks one gets 403 `insufficient_scope`. Empty means no scope requirement. |
| `auth.oidc.jwks_cache_ttl` | `ARGVIO_AUTH__OIDC__JWKS_CACHE_TTL` | duration | `15m` | How long a fetched JWKS is cached before being refreshed. If a refresh fails, the previous keys keep being used. A token naming an unrecognized `kid` triggers one immediate refresh regardless of this TTL (to pick up key rotation), at most once per 10s so random kids cannot turn into a flood of requests to the provider. |
| `auth.oidc.require_access_token_typ` | `ARGVIO_AUTH__OIDC__REQUIRE_ACCESS_TOKEN_TYP` | bool | `false` | When true, a JWT whose header has a `typ` other than `at+jwt` (RFC 9068) is rejected, as an extra guard against ID tokens. A token with no `typ` header is still judged by its audience. Leave false for providers that do not set `typ` to `at+jwt` on access tokens. |
| `auth.oidc.trust_tenant_id_claim` | `ARGVIO_AUTH__OIDC__TRUST_TENANT_ID_CLAIM` | bool | `false` | Unsafe-by-design escape hatch, off by default. Normally a user's tenant comes from tenant_members (see `argvio tenant member`) and a `tenant_id` claim, if the token carries one, must itself be a membership or the request gets 403 `no_tenant_access`. When true, a `tenant_id` claim selects the tenant without a membership, trusting the provider to assign it. |
| `auth.oidc.introspection.enabled` | `ARGVIO_AUTH__OIDC__INTROSPECTION__ENABLED` | bool | `false` | Verify opaque (non-JWT, non-`argv_`) access tokens with the provider's RFC 7662 introspection endpoint. Requires oidc in auth.methods and client_id/client_secret. A token is accepted only if `active`, its `aud` contains oidc.audience (the response must include `aud`), `iss` (when present) matches, `exp`/`nbf` are valid and required_scopes are present. |
| `auth.oidc.introspection.endpoint` | `ARGVIO_AUTH__OIDC__INTROSPECTION__ENDPOINT` | string | `` | Introspection endpoint URL. Defaults to the discovery document's `introspection_endpoint`; startup fails if introspection is enabled and neither is available. Redirects are never followed. |
| `auth.oidc.introspection.client_id` | `ARGVIO_AUTH__OIDC__INTROSPECTION__CLIENT_ID` | string | `` | Client ID this API uses to authenticate to the introspection endpoint (client_secret_basic). Required when introspection is enabled. |
| `auth.oidc.introspection.client_secret` | `ARGVIO_AUTH__OIDC__INTROSPECTION__CLIENT_SECRET` | string | `` | Client secret for the introspection endpoint. Required when introspection is enabled; prefer the ARGVIO_AUTH__OIDC__INTROSPECTION__CLIENT_SECRET env var over a file. |
| `auth.oidc.introspection.cache_ttl` | `ARGVIO_AUTH__OIDC__INTROSPECTION__CACHE_TTL` | duration | `60s` | How long an active introspection result is reused, capped by the token's own `exp`. Results are cached by the SHA-256 of the token (the token itself is never stored or logged). This is also the revocation latency: a token revoked at the provider may keep working for up to this long. |
| `auth.oidc.introspection.negative_cache_ttl` | `ARGVIO_AUTH__OIDC__INTROSPECTION__NEGATIVE_CACHE_TTL` | duration | `5s` | How long a rejection (inactive, wrong audience, missing scope) is remembered, to blunt retry storms with a bad token. Provider failures are never cached. |
| `auth.admin.oidc.issuer_url` | `ARGVIO_AUTH__ADMIN__OIDC__ISSUER_URL` | string | `` | Admin identities (metrics server only; off unless an admin recognition rule is configured, see docs/architecture.md): issuer that verifies admin access tokens. Unset = auth.oidc.issuer_url, i.e. the same IdP, which is the common case. Same exact-match rules as auth.oidc.issuer_url. |
| `auth.admin.oidc.audience` | `ARGVIO_AUTH__ADMIN__OIDC__AUDIENCE` | string | `` | Audience every admin token's `aud` must contain. Unset = auth.oidc.audience. Set it to a different resource identifier to keep admin tokens distinct from user tokens, so a user token can never be an admin token. |
| `auth.admin.oidc.required_scopes` | `ARGVIO_AUTH__ADMIN__OIDC__REQUIRED_SCOPES` | []string | `` | Scopes an admin token must carry. Empty = auth.oidc.required_scopes (so it cannot be used to require none). |
| `auth.admin.oidc.jwks_cache_ttl` | `ARGVIO_AUTH__ADMIN__OIDC__JWKS_CACHE_TTL` | duration | `` | Unset = auth.oidc.jwks_cache_ttl. |
| `auth.admin.oidc.introspection.enabled` | `ARGVIO_AUTH__ADMIN__OIDC__INTROSPECTION__ENABLED` | bool | `` | Verify opaque admin tokens by introspection. Unset = auth.oidc.introspection.enabled when the admin issuer is the same as auth.oidc.issuer_url, otherwise false. |
| `auth.admin.oidc.introspection.endpoint` | `ARGVIO_AUTH__ADMIN__OIDC__INTROSPECTION__ENDPOINT` | string | `` | Unset = auth.oidc.introspection.endpoint when the admin issuer is the same, otherwise the admin issuer's discovery document. |
| `auth.admin.oidc.introspection.client_id` | `ARGVIO_AUTH__ADMIN__OIDC__INTROSPECTION__CLIENT_ID` | string | `` | Unset = auth.oidc.introspection.client_id when the admin issuer is the same. A different issuer never inherits it, so one provider's client credentials are never sent to another. |
| `auth.admin.oidc.introspection.client_secret` | `ARGVIO_AUTH__ADMIN__OIDC__INTROSPECTION__CLIENT_SECRET` | string | `` | Unset = auth.oidc.introspection.client_secret when the admin issuer is the same; never inherited by a different issuer. | `auth.admin.oidc.introspection.cache_ttl` | `ARGVIO_AUTH__ADMIN__OIDC__INTROSPECTION__CACHE_TTL` | duration | `` | Unset = auth.oidc.introspection.cache_ttl. Also the revocation latency for admin tokens. |
| `auth.admin.oidc.introspection.negative_cache_ttl` | `ARGVIO_AUTH__ADMIN__OIDC__INTROSPECTION__NEGATIVE_CACHE_TTL` | duration | `` | Unset = auth.oidc.introspection.negative_cache_ttl. |
| `auth.admin.claim.name` | `ARGVIO_AUTH__ADMIN__CLAIM__NAME` | string | `` | Admin recognition by claim, with claim.value: the claim to read from the verified access token (the JWT payload, or the introspection response for an opaque token; never a request header or the ID token). It may be a string or an array of strings, e.g. `groups`. Empty = rule off. Setting only one of name and value is a startup error. **Trust caveat:** access now depends on this claim, so it is only as trustworthy as your IdP's control over it. Never use a claim a user can edit; use a dedicated IdP group, and consider auth.admin.oidc.audience / required_scopes so ordinary user tokens cannot qualify. |
| `auth.admin.claim.value` | `ARGVIO_AUTH__ADMIN__CLAIM__VALUE` | string | `` | The value that grants admin: matched exactly and case-sensitively (no wildcards or regex) against a string claim, or against any element of an array claim. A space-separated string such as `scp` is not split. Empty = rule off. |
| `auth.admin.subjects` | `ARGVIO_AUTH__ADMIN__SUBJECTS` | []string | `[]` | Admin recognition by allowlist: `sub` values of admins, matched together with the admin issuer (auth.admin.oidc.issuer_url, else auth.oidc.issuer_url) byte for byte against the verified token's `iss` and `sub`; comma-separated in the env var. Entries are trimmed, empty ones and duplicates ignored, no wildcards. Empty = rule off. Works alongside the claim rule: either grants admin. Changes need a restart, and removing a `sub` and redeploying revokes the admin. See docs/running-locally.md for finding your `sub`. |
| `auth.admin.role` | `ARGVIO_AUTH__ADMIN__ROLE` | string | `viewer` | Role every admin identity has in every tenant: `viewer` (read access to metrics) or `admin` (also what future write endpoints will require; same as viewer on today's read-only API). Unknown names fail startup. Keep it `viewer` unless needed; admin recognition never implies write access by itself. |
| `auth.admin.role_claim` | `ARGVIO_AUTH__ADMIN__ROLE_CLAIM` | string | `` | Optional claim of the verified token that may set the admin's role (`viewer` or `admin`) instead of auth.admin.role. A missing claim uses auth.admin.role silently; a claim holding anything else (unknown name, wrong type) also uses auth.admin.role and is logged as a warning. Like claim.name, the claim can raise the role to `admin`, so it needs the same IdP trust. |

## Per-tenant overrides

Stored in Postgres (`tenant_config` table), not static config — they change per-customer at runtime via `argvio tenant config`. See docs/schema.md.

| Column | Meaning |
|---|---|
| `tier_ceiling` | Max consent tier this tenant may send (anonymous/basic/full/optin_plus). |
| `tier_enforcement_mode` | `strip` or `reject` when a record's declared tier exceeds the ceiling. |
| `rate_limit_requests_per_sec` / `rate_limit_bytes_per_sec` / `rate_limit_burst` | Override the public server's global rate-limit defaults. NULL = use global default. |
| `retention_traces_days` / `retention_logs_days` / `retention_metrics_days` | Shorter-than-global retention, enforced by `argvio retention sweep` (see docs/schema.md). NULL = use the global Timescale retention policy. |
